# 买方深度研究 V2：公司定价版

## 一、定位

本 skill 的目标不是写一篇“资料很全”的报告，而是写一篇**能服务投资判断的买方深度研究**。

核心任务：

> 把公司业务和产业逻辑翻译成投资语言，说明这家公司到底靠什么赚钱，市场为什么给这个估值，当前市值隐含什么预期，核心变量成立/不成立分别值多少钱。

报告必须围绕一条主线展开：

> 公司是谁 → 生意怎么赚钱 → 利润为什么这样 → 市场在赌什么 → 当前估值隐含什么 → 核心变量如何验证 → 成立/不成立分别怎么定价 → 结论。

---

## 二、最高优先级原则

### 1. 先写给“金融背景但无产业经验的人”看

正式分析前，必须先完成“读者翻译层”。

| 问题 | 必须回答 |
|---|---|
| 公司一句话是什么 | 不超过50字，讲商业本质，不讲概念 |
| 它卖什么 | 拆成具体产品/服务，不只写业务板块名称 |
| 谁买 | 客户类型、预算来源、采购决策人 |
| 为什么买 | 降本、提效、合规、安全、替代、体验、AI化等 |
| 怎么收费 | 一次性、订阅、项目制、运维费、分成、硬件+软件等 |
| 怎么赚钱 | 收入、毛利率、费用率、现金流、规模效应 |
| 股价看什么 | 1-3个真正的核心定价变量 |

禁止只写“公司是AI/信创/国产替代/数字经济/出海受益标的”。必须写清楚收入和利润传导。

### 2. 不是把所有信息都写进去，而是只保留能解释估值的信息

每一章都要回答：**这件事如何影响收入、利润、现金流、估值或风险？**

如果不能影响这些变量，就不要展开。

### 3. 核心结论必须二元化

买方报告不能只有“长期看好，但短期关注风险”。必须写清：

| 情况 | 结论 |
|---|---|
| 核心变量成立 | 公司应该值多少钱，为什么 |
| 核心变量不成立 | 公司应该值多少钱，为什么 |
| 当前价格 | 更接近哪种情景，隐含什么预期 |
| 预期差 | 市场可能错在哪里 |

## 三、证据分级

| 证据等级 | 类型 | 报告中如何使用 |
|---|---|---|
| 强证据 | 年报、季报、公告、招股书、交易所问询回复 | 可作为核心判断依据 |
| 中强证据 | 行业数据库、官方政策、招投标、客户资本开支、IDC/Gartner等 | 用于验证产业景气和竞争格局 |
| 预期证据 | 券商盈利预测、目标价、评级变化、一致预期 | 用于判断市场预期和price-in程度 |
| 弱证据 | 调研纪要、雪球产业链口径、专家访谈、媒体报道 | 只能作为线索，必须标注不确定性 |
| 叙事参考 | 海外对标、未上市公司估值、概念映射 | 只用于解释估值想象空间，不能直接套倍数 |

报告中涉及关键判断时，必须说明证据属于哪一类。

## 四、工作流程

## 阶段0：确认公司身份和研究问题

先确认：代码、主营业务、上市地点、实控人、业务结构、市值、当前估值、最近一个季度的核心变化。

然后先给出“研究问题”：

> 这家公司当前最大的定价争议是：【争议点】。市场看多者认为【看多逻辑】，看空者担心【看空逻辑】。本文要验证的是【1-3个核心变量】。

输出：

| 项目 | 内容 |
|---|---|
| 公司一句话 | |
| 当前市值/估值 | |
| 市场交易逻辑 | 成长/修复/红利/资产/主题/困境反转 |
| 最大争议 | |
| 核心定价变量 | 不超过3个 |

---

## 阶段1：并行研究模块

如果环境支持 subagent，则同一条消息中并行发起5个 `subagent_spawn(type="research")`。如果不支持，则按5个模块独立检索。

### 模块1：业务与收入拆分

- 每块业务卖什么具体产品/服务
- 业务来源：自研、收购、代理、合作、转型延伸
- 客户是谁，预算从哪里来
- 收入确认方式：一次性、项目制、订阅、服务费、硬件、软件、分成
- 近3-5年收入增速、占比、毛利率变化

### 模块2：财务质量和利润模型

- 收入、毛利率、销售费用率、研发费用率、管理费用率、净利率
- 现金流、应收账款、存货、合同负债、商誉、有息负债
- 杜邦拆解：利润变化来自收入、毛利率、费用率、资产周转还是杠杆
- 判断利润是“收入驱动”“费用驱动”“价格驱动”“资产处置驱动”还是“一次性因素”

### 模块3：产业链和竞争格局

- 产业链上下游
- 客户采购逻辑和采购周期
- 行业为什么变化：A变化 → B客户行为变化 → C订单变化 → D公司收入/利润变化
- 主要竞争对手
- 进入壁垒：客户、渠道、技术、成本、牌照、生态、数据、品牌

### 模块4：可比公司和估值体系

可比公司不能只按概念选，必须按“市场交易逻辑”选。

至少分三类：

| 类别 | 说明 |
|---|---|
| 直接业务可比 | 同业务、同客户、同收入模式 |
| 估值逻辑可比 | 市场同样在交易成长、修复、红利、资产或主题 |
| 叙事参考可比 | 海外龙头/未上市公司/平台型公司，只用于理解空间 |

对比必须包含：业务本质、客户结构、收入模式、毛利率、费用率、现金流、核心变量、风险来源、估值差异原因。

### 模块5：筹码、催化剂和资本运作

- 股东结构、实控人、管理层持股
- 减持、回购、股权激励、质押、解禁
- 分红、并购、资产出售、定增、员工持股
- 未来1个月、1个季度、1年的催化剂时间线
- 哪些催化剂是确定发生，哪些只是预期

## 阶段2：逻辑链融合

按以下顺序写，不允许跳跃。

### 1. 一句话定义公司

格式：

> [公司]本质上是一家【商业本质】公司，当前市场不是在交易【表面标签】，而是在交易【核心变量】。

### 2. 生意模式拆解

必须用表格：

| 业务 | 卖什么 | 谁买 | 为什么买 | 收费方式 | 收入占比 | 毛利率/利润特征 | 核心变量 |
|---|---|---|---|---|---:|---|---|

### 3. 利润模型拆解

解释公司利润为什么高/低/改善/恶化。

必须写清：

- 是收入增长带来的利润，还是费用下降带来的利润？
- 毛利率变化是产品结构变化、价格战、成本变化，还是会计因素？
- 费用率是否还能继续下降？如果不能，利润弹性是否会消失？
- 现金流是否支持利润？

### 4. 产业变化如何传导到公司

禁止写“行业景气，公司受益”。必须写成链条：

```text
产业变化A
  → 客户行为变化B
  → 订单/价格/采购周期变化C
  → 公司收入/毛利率/费用率变化D
  → 利润和估值变化E
```

### 5. 当前市值隐含预期

这是本 skill 的核心。

必须回答：

| 问题 | 要求 |
|---|---|
| 当前市值对应多少PE/PS/PB/EV等 | 选择适合公司阶段的指标 |
| 这个估值隐含未来多少利润/收入/利润率 | 反推，不只引用券商预测 |
| 要支撑当前估值，未来1-3年需要什么增长 | 写成具体指标 |
| 市场已经price-in什么 | 已反映的预期 |
| 市场还没price-in什么 | 潜在预期差 |
| 最大风险是什么 | 哪个变量一旦错，估值会重估 |

### 6. 估值方法

根据公司类型选择，不要机械套PE。

| 公司类型 | 优先估值方法 |
|---|---|
| 稳定盈利公司 | PE、DCF、股息率 |
| 高增长但利润低 | PS、远期PE、单位经济模型 |
| 周期股 | PB、吨盈利、产能价值、周期位置 |
| 现金牛/资产型 | 现金价值、分红能力、SOTP、EV/EBITDA |
| 平台/转型公司 | 分部估值、核心业务+新业务期权 |
| 亏损成长公司 | 收入增速、毛利率、现金消耗、PS、盈亏平衡路径 |

分部估值时必须说明每一块：为什么用这个方法、对标谁、倍数为什么合理、低中高三种情景。

### 7. 核心变量二元化

输出：

| 变量 | 成立条件 | 不成立条件 | 验证指标 | 时间点 |
|---|---|---|---|---|

然后给出估值区间：

| 情景 | 核心假设 | 收入/利润假设 | 合理估值方法 | 合理市值/股价区间 | 概率 |
|---|---|---|---|---|---:|

## 五、输出格式

```markdown
# [公司]买方深度研究：市场到底在赌什么

## 0. 研究问题和一句话结论

## 1. 先把公司讲明白：它到底卖什么，怎么赚钱

## 2. 业务拆分：每块业务从哪来、卖给谁、怎么收费

## 3. 财务拆解：利润为什么这样，质量怎么样

## 4. 行业变化如何传导到公司

## 5. 竞争格局：它和谁竞争，优势到底硬不硬

## 6. 可比公司：谁是真可比，谁只是叙事参考

## 7. 当前市值隐含了什么预期

## 8. 估值：核心变量成立/不成立分别值多少钱

## 9. 催化剂、筹码和资本运作

## 10. 风险和证伪条件

## 11. 结论：买的是什么，错的风险是什么
```

## 六、写作规范

1. 每章开头先用一句话回答“这一章要解决什么投资问题”。
2. 每个重要结论后必须跟一句“为什么”。
3. 数据放表格，判断写在表格后面。
4. 术语第一次出现必须解释。
5. 对比必须说明“为什么可比/为什么不可比”。
6. 结论必须能落到投资动作或跟踪指标。
7. 不要为了显得专业而堆概念。
8. 不要把研报观点当事实。
9. 不要把海外高估值直接套给A股公司。
10. 不要用“长期空间广阔”代替盈利模型。
