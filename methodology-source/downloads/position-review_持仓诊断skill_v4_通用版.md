# 持仓诊断（通用逻辑复盘文章版）

## 一、定位：回答“上涨逻辑还在不在”

持仓诊断不是重新写公司深度，也不是重新解释行业常识。用户已经做过行业研究和买入分析，现在真正要解决的是：

> 当初为什么涨？后来为什么跌？上涨逻辑有没有消失？下跌原因有没有解决？当前位置是错杀、证伪、预期降温，还是赔率不够？

最终输出必须是一篇有时间线、有市场叙事、有多空复盘、有操作结论的文章。不要写成表格堆叠，不要重新把公司业务介绍一遍。

---

## 二、通用原则

### 1. 先还原股价故事，再做判断

不能一上来写“当前矛盾是……”。必须先讲：

- 从什么时候开始涨；
- 为什么涨；
- 涨到什么位置；
- 上涨过程中逻辑有没有升级；
- 从什么时候开始跌；
- 为什么跌；
- 跌的时候市场真正担心什么；
- 现在这些担心是否还在。

如果没有股价区间、时间线或公告资料，必须说明信息不足，并根据已有资料谨慎判断，不能编造。

### 2. 上涨逻辑和下跌逻辑必须分开

必须分清：

- 上涨时市场买的是什么；
- 下跌时市场卖的是什么；
- 两者是不是同一个变量；
- 下跌有没有真正伤到上涨逻辑。

如果上涨是因为业绩和订单，下跌却是因为减持、解禁、定增、可转债、市场风格或获利盘，那可能是筹码/估值冲击；如果下跌是因为订单低于预期、毛利率下降、收入放缓、客户流失或现金流恶化，那就是基本面伤害。

### 3. 必须找“逻辑质变时刻”

上涨通常不是一次性完成的，可能经历：

- 第一阶段：事件催化；
- 第二阶段：业绩验证；
- 第三阶段：产业趋势；
- 第四阶段：估值重估；
- 第五阶段：情绪过热。

必须判断：股价从修复变成趋势，从趋势变成泡沫，是在哪个时刻发生的。

### 4. 下跌原因必须分类

每个下跌原因必须归类：

- 基本面证伪：收入、订单、毛利率、利润、现金流等核心变量变差；
- 预期降温：逻辑没错，但市场原来预期太高；
- 筹码冲击：减持、解禁、定增、可转债、融资盘、基金调仓；
- 估值压缩：业绩没变，但倍数下降；
- 情绪冲击：主题退潮、板块轮动、获利盘；
- 外部扰动：政策、监管、地缘、汇率、利率；
- 会计扰动：一次性费用、股份支付、汇兑、减值、补贴变化；
- 流动性冲击：市场整体风险偏好下降。

分类之后必须回答：这个因素是短期可逆，还是长期压制？

### 5. 必须审判原始买入逻辑

逐条检查原来的上涨逻辑：

- 当时的核心变量是什么；
- 当时市场相信什么；
- 当时证据是什么；
- 现在证据有没有更新；
- 逻辑是更强、持平、变弱、证伪，还是只是情绪主题；
- 市场是否已经 price-in；
- 下一步需要什么验证。

### 6. 必须判断错杀、证伪、还是赔率不足

结论不能只写“持有/减仓”。必须判断当前位置性质：

- 错杀：下跌原因没有伤到核心逻辑，且压制因素可逆；
- 证伪：下跌原因直接伤到原始买入逻辑；
- 预期降温：逻辑还在，但市场原来给太高估值；
- 赔率不足：公司没问题，但价格已经反映太多；
- 等待验证：核心逻辑尚未证伪，但缺关键财报或订单；
- 趋势退潮：主题催化消失，基本面还没接上。

### 7. 操作必须来自逻辑

必须回答：

- 继续持有的理由是什么；
- 加仓是在赌哪个变量；
- 减仓是因为逻辑证伪、估值太贵、风险不可控，还是仓位管理；
- 什么触发条件改变结论；
- 已有持仓、新开仓、重仓、被套分别怎么处理。

不能因为“股价跌了”就加仓，也不能因为“有利空”就减仓。关键是利空有没有伤到原始买入逻辑。

### 8. 少用表格，保留文章感

最多使用两张表：

1. 股价与事件时间线；
2. 操作触发条件。

其他部分尽量用连续文字。表格只能辅助，不能替代判断。

## 三、必须检查的信息源

如果用户提供数据库、研报库、公告库或调研纪要，必须优先使用。

需要尽量检查：

- 公司公告：减持、解禁、定增、可转债、股权激励、回购、业绩预告、并购；
- 财报：收入、订单、毛利率、费用率、净利、扣非、现金流；
- 研报时间线：卖方什么时候上调或下调逻辑和目标价；
- 调研纪要：公司如何回应市场关注；
- 股价区间：上涨和下跌分别对应哪些时间；
- 同行业表现：公司单独跌，还是板块一起跌；
- 筹码变化：高管、股东、基金、北向、融资盘；
- 市场风格：主题退潮、成长/价值切换、流动性变化。

证据不足时必须标注“不确定”，不能装作确定。

## 四、通用研究流程

### Phase 1：还原持仓故事

开头写成文章：

> 这笔持仓现在要回答的不是公司好不好，而是原来推动股价上涨的那套逻辑，到今天还剩多少。它从 A 到 B 的上涨，交易的是某种预期；从 B 到 C 的回落，表面原因是某个事件，但深层原因可能是市场开始怀疑这个预期能否兑现。

实际写作时必须根据具体公司重写，不能照抄。

### Phase 2：拆上涨逻辑

按时间线拆：

1. 第一波上涨由什么催化；
2. 第二波上涨有没有逻辑升级；
3. 市场从买事件，是否变成买产业趋势或业绩重估；
4. 股价高点隐含了什么预期；
5. 哪些证据当时支撑上涨。

重点不是列事件，而是解释事件为什么让市场愿意提高估值。

### Phase 3：拆下跌原因

把下跌写成多层：

- 表面原因：市场看到的直接事件；
- 深层原因：资金真正担心的变量；
- 逻辑伤害：伤的是基本面、估值、筹码、情绪还是流动性；
- 持续性：压制是否还在；
- 可逆性：什么出现后可以解除。

例如减持不能只写“减持利空”。必须分析谁减持、减持规模、发生在什么股价阶段、是否改变基本面、市场为什么担心、减持结束后压制是否解除。

### Phase 4：审判原始逻辑

对每条原始逻辑做判断：

- 已验证且更强；
- 仍在验证；
- 被部分削弱；
- 已证伪；
- 只是情绪主题，无法验证。

必须解释原因，不能只给状态。

### Phase 5：判断当前位置赔率

必须回答：

- 当前价格反映了哪些悲观；
- 还没反映哪些风险；
- 如果逻辑恢复，向上空间来自业绩、估值修复还是事件催化；
- 如果逻辑证伪，向下风险来自利润下修还是估值压缩；
- 现在是高胜率低赔率，还是低胜率高赔率；
- 现在更适合持有、加仓、减仓，还是等待验证。

### Phase 6：操作结论

结论用文章段落写，然后用一张触发条件表辅助。

必须分别考虑：

- 已有持仓：持有、减仓、加仓、等待验证；
- 新开仓：是否适合现在买；
- 重仓：是否需要降风险；
- 被套：是等验证、补仓，还是承认证伪。

## 五、推荐输出结构

```markdown
# [公司]持仓诊断：上涨逻辑还在吗，下跌是在错杀还是证伪

## 引言：这笔持仓现在真正要回答的问题
用连续段落描述股价故事和当前疑问。

## 一、先还原股价路径：它是怎么涨上去，又怎么跌下来的
讲清楚时间线，可附一张事件表。

## 二、上涨时市场在买什么
拆清楚第一波、第二波、逻辑升级和估值扩张。

## 三、下跌时市场在卖什么
分析基本面、估值、筹码、情绪、外部因素。

## 四、原始买入逻辑现在还剩多少
逐条审判核心逻辑是否仍成立。

## 五、当前位置的赔率
判断错杀、证伪、预期降温、赔率不足或等待验证。

## 六、操作结论
给出已有持仓、新开仓、重仓、被套情况下的处理方式和触发条件。
```

## 六、质量检查清单

输出前必须确认：

- 是否还原了上涨和下跌的完整故事？
- 是否区分了上涨逻辑和下跌逻辑？
- 是否找到了逻辑质变时刻？
- 是否分析了下跌原因是否伤到核心逻辑？
- 是否检查了减持、解禁、定增、可转债、业绩、现金流等关键风险？
- 是否判断了错杀、证伪、预期降温或赔率不足？
- 是否给出了来自逻辑的操作结论？
- 是否避免重新写公司深度？
- 是否避免表格堆叠和 emoji？
- 是否对证据不足的地方保持诚实？
